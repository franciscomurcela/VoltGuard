Mini-Spec: Composer -> Anomaly (Datasets) + Anomaly -> Composer (Webhooks)

Objetivo
- Composer obtem datasets externos (UCI/OPSD), normaliza os dados e envia para a API de anomalias.
- API de anomalias processa com Prophet e notifica o Composer via webhook.

Fontes de datasets
1) UCI Household Electric Power Consumption
  https://archive.ics.uci.edu/static/public/235/individual+household+electric+power+consumption.zip

2) OPSD Germany Daily
  https://raw.githubusercontent.com/jenfly/opsd/master/opsd_germany_daily.csv

Fluxo
1) Composer agenda job periodico (ex: 60s).
2) Composer faz GET dos datasets nas URLs acima.
3) Composer parseia/normaliza para lista de pontos {timestamp, value}.
4) Composer faz POST /v1/measurements na Anomaly API para cada dataset/sensor.
5) Anomaly processa dataset (train/forecast/anomalias).
6) Anomaly envia webhook para Composer (measurement_processed e/ou anomaly_detected).

Endpoint de ingestão (Anomaly)
- Método: POST
- URL: http://anomaly-api:8085/v1/measurements (docker) ou http://localhost:8085/v1/measurements (local)
- Headers:
  - Content-Type: application/json
  - X-App-Token: token_do_composer_123

Payload (request)
{
  "source_id": "sensor_001",
  "metric_name": "voltage",
  "config": {
    "train_ratio": 0.8,
    "temporal_mode": "hourly",
    "aggregation": "none",
    "timezone": "UTC"
  },
  "dataset": [
    { "timestamp": "2026-03-01T00:00:00Z", "value": 220.1 },
    { "timestamp": "2026-03-01T01:00:00Z", "value": 221.3 },
    { "timestamp": "2026-03-01T02:00:00Z", "value": 219.8 },
    { "timestamp": "2026-03-01T03:00:00Z", "value": 224.4 },
    { "timestamp": "2026-03-01T04:00:00Z", "value": 218.9 },
    { "timestamp": "2026-03-01T05:00:00Z", "value": 226.2 }
  ]
}

Mapeamento de colunas recomendado
- UCI:
  - timestamp = Date + " " + Time
  - value = Global_active_power
  - metric_name = global_active_power

- OPSD:
  - timestamp = Date
  - value = Consumption
  - metric_name = consumption

Resposta esperada (sucesso)
- HTTP 202 Accepted
- body com measurement_id, rows_received, rows_training, rows_forecast, status.

Regras de validação mínimas
1) dataset com pelo menos 6 pontos.
2) timestamp em ISO (YYYY-MM-DDTHH:mm:ssZ).
3) value numérico.
4) train_ratio entre 0.5 e 0.95.

Política de retries/timeouts no Composer
1) Timeout por request: 20s.
2) Retries: 2 tentativas adicionais com backoff (ex: 1s, 3s).
3) Não reenviar infinito.
4) Se 422, tratar como erro de payload (não retry automático sem correção).

Idempotência recomendada
- Incluir request_id/batch_id nos logs do Composer para evitar duplicações em retries.
- Opcional: manter hash do último lote enviado por sensor.

Webhooks (Anomaly -> Composer)
- Composer expõe endpoint, por exemplo: POST /v1/anomalies/webhook
- Anomaly envia payload:
{
  "event_type": "anomaly_detected",
  "sent_at": "2026-04-13T10:00:00Z",
  "payload": {
    "anomaly_id": "ANM-...",
    "measurement_id": "meas_...",
    "source_id": "sensor_001",
    "metric_name": "voltage",
    "timestamp": "2026-03-01T03:00:00",
    "severity": "HIGH"
  }
}

Eventos usados
- measurement_processed
- anomaly_detected

Config que deve ficar alinhada
- Anomaly .env:
  - VG_APP_TOKEN=token_do_composer_123
  - VG_COMPOSER_WEBHOOK_URL=http://composer-backend:8080/v1/anomalies/webhook
- Composer:
  - URLs dos datasets UCI/OPSD configuradas
  - URL de ingestão da Anomaly
  - token X-App-Token
  - scheduler periódico ativo

Checklist de teste E2E
1) Anomaly GET /v1/health => UP.
2) Composer envia POST /v1/measurements => 202.
3) Anomaly lista dataset em GET /v1/measurements.
4) Anomaly gera registos em GET /v1/anomalies.
5) Composer recebe webhook(s) com 2xx.
